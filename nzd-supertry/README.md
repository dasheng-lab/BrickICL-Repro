# nzd-supertry：掩码顺序数据增强

> 状态：第 1–5 步都已完成第一轮（2026-11-11）。
> 结果：在 `M` 需要跳接的补全题上，增强组把零件放对的指标约为对照组的 2 倍（整块正确 1.6% → 3.1%），
> 不需要跳接时三个模型没有差别，原有能力没有受损；但绝对正确率仍然很低。详见 [`step5_eval/`](step5_eval/README.md)。
> 中途发现官方训练数据是深度优先顺序，采样算法和数据已按此改过一版（`v2`），详见 [`step4_train/`](step4_train/README.md)。
> 本目录是 Zidong 的独立尝试，代码和说明都放在这里，不改动 `brickicl/`。

## 思路

对每个乐高模型选多个不同的缺失子装配 `M`，每个 `M` 采一条"先拼 `G \ M`、再拼 `M`"的合法序列。
这些序列当作普通的 BrickNet-PT 训练数据：整条序列算 loss，不带自然语言描述，序列里不标记 `M` 从哪里开始。
在官方 BrickNet-PT 权重上做 LoRA 后训练。

补全不完整序列只是推理时的测试方法：给 `G \ M` 的前缀，让模型写出 `M`。

**为什么改顺序而不是加数量**：官方 PT 已经用了约 809 万条序列，平均每个模型约 25 种随机顺序。
这些序列全部是深度优先顺序：每个零件接在上一个零件或它的祖先上。"回到别处的早期零件接一整块新结构"从不出现，
而补全 `M` 时恰恰需要这样做。这个增强改变的是顺序的分布，让"`M` 排最后"成为训练数据的一部分。

## 三组对照

| 组 | 训练数据 | loss | 用途 |
|---|---|---|---|
| 冻结 PT | 无 | — | 基线 |
| 对照 | 同一棵搭建树的深度优先顺序，数量相同 | 整条序列 | 排除"只是多训了几步" |
| 增强 | 同一棵树，把 `M` 这一段挪到最后 | 整条序列 | 只差 `M` 的位置 |

训练模型取自 pt / sft，测试全部用 val，两边在模型层面不重叠。

## 运行

目录名带连字符，不能当 Python 包导入，脚本都从仓库根目录直接运行：

```bash
source brickicl/env.sh
python nzd-supertry/step2_sampler/test_sampler.py -v
python nzd-supertry/step3_data/build_data.py --split sft --models 2000 --out runs/nzd-supertry/sft_2k
```

数据和实验输出放在 `runs/nzd-supertry/`，不入库，规则与仓库其余部分相同。
