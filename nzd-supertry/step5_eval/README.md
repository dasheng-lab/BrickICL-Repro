# 第 5 步：评测

> 状态：完成（2026-11-11）。三个模型在 val 的 1,208 条补全题上评测完毕。

在 val 的模型上比较三个模型：冻结的官方 BrickNet-0.6B-PT、对照组（`plain`）、增强组（`masked`）。
测试方法就是最初设想的补全：给模型看 `G \ M`，让它把 `M` 写出来。

## 结果（2026-11-11）

**结论：增强有效，而且效果只出现在它该出现的地方；但补全的绝对正确率仍然很低。**

- 在 `M` 需要跳接的题目上，增强组把零件放对的几项指标约为对照组的 2 倍，差别都显著。
- 在不需要跳接的题目上，三个模型没有差别。
- 对照组和冻结模型几乎一样，说明提升不是"多训了几步"带来的。
- 在官方自带的序列上，三个模型的 loss 相同，后训练没有损害原有能力。
- 即使是增强组，需要跳接时整块 `M` 完全写对的也只有 3.1%，仍有 62% 的样本沿着老习惯接在当前路径上。

用的 checkpoint：对照组第 1750 步，增强组第 2000 步（各自开发集 loss 最低）。下面的比例都是 8 个样本的平均。
"差"一列的方括号是 95% 置信区间。

### 需要跳接的题目（800 条，383 个模型）

`M` 的接入点不在当前路径上。这是官方训练数据里从不出现、增强想教会模型的情况。

| 指标 | 冻结 | 对照 | 增强 | 增强 − 对照 |
|---|---:|---:|---:|---:|
| 整块 `M` 完全正确 | 1.3% | 1.6% | 3.1% | +1.5 [+0.9, +2.2] |
| `M` 的零件放对的比例 | 1.9% | 2.4% | 5.2% | +2.8 [+2.2, +3.6] |
| 第一个零件放对 | 2.3% | 2.8% | 6.4% | +3.6 [+2.7, +4.5] |
| 零件和颜色对，不管位置 | 13.6% | 14.6% | 18.0% | +3.4 [+2.5, +4.4] |
| 第一个零件接在参考接入点上 | 1.8% | 2.6% | 13.2% | +10.5 [+9.1, +12.0] |
| 第一个零件接在当前路径上 | 94.3% | 93.3% | 62.1% | −31.2 [−33.6, −28.7] |
| 补全能解析 | 94.8% | 94.4% | 93.5% | −0.8 [−1.8, +0.2] |
| 参考答案 `M` 的 loss（每 token） | 0.474 | 0.480 | 0.288 | −0.192 [−0.211, −0.175] |

8 个样本里至少有一个的情况：

| | 冻结 | 对照 | 增强 |
|---|---:|---:|---:|
| 至少一个样本整块正确 | 3.0% | 3.6% | 6.4% |
| 至少一个样本第一个零件放对 | 6.4% | 7.0% | 18.0% |

第一个零件接在哪（需要跳接的题目，全部样本）：

| | 冻结 | 对照 | 增强 |
|---|---:|---:|---:|
| 当前路径上（深度优先的习惯） | 94.3% | 93.3% | 62.1% |
| 参考接入点 | 1.8% | 2.6% | 13.2% |
| 别的不在路径上的零件 | 1.1% | 1.5% | 22.1% |
| 没写出合法的第一个零件 | 2.7% | 2.5% | 2.6% |

冻结模型和对照组几乎从不离开当前路径。增强组有 35% 的样本会跳出去，其中约三分之一跳到了参考接入点。

### 不需要跳接的题目（408 条，285 个模型）

`M` 的接入点本来就在当前路径上，掩码序列仍是合法的深度优先序列。

| 指标 | 冻结 | 对照 | 增强 | 增强 − 对照 |
|---|---:|---:|---:|---:|
| 整块 `M` 完全正确 | 8.0% | 8.3% | 8.0% | −0.3 [−0.8, +0.2] |
| `M` 的零件放对的比例 | 13.3% | 13.8% | 13.6% | −0.2 [−0.7, +0.4] |
| 第一个零件放对 | 15.3% | 16.0% | 15.7% | −0.3 [−1.0, +0.4] |
| 第一个零件接在当前路径上 | 99.0% | 99.2% | 94.4% | −4.8 [−6.1, −3.6] |
| 补全能解析 | 97.2% | 97.3% | 95.8% | −1.5 [−2.2, −0.8] |
| 参考答案 `M` 的 loss（每 token） | 0.239 | 0.234 | 0.234 | 0.000 [−0.001, +0.001] |

正确率没有差别。增强组有一点副作用：约 5% 的样本在不该跳的时候跳了，能解析的比例低 1.5 个百分点。

这一组也给出了参照：不需要跳接时，冻结模型第一个零件放对的比例是 15%。增强把需要跳接时的这个比例从 2.3% 提到 6.4%，
补上了差距的三分之一左右。两组题目的 `M` 本身也不一样，这个对比只是量级上的参考。

### 全部题目（1,208 条，442 个模型）

| 指标 | 冻结 | 对照 | 增强 | 对照 − 冻结 | 增强 − 对照 |
|---|---:|---:|---:|---:|---:|
| 整块 `M` 完全正确 | 3.5% | 3.8% | 4.8% | +0.3 [+0.1, +0.5] | +0.9 [+0.5, +1.4] |
| `M` 的零件放对的比例 | 5.8% | 6.2% | 8.0% | +0.4 [+0.2, +0.7] | +1.8 [+1.3, +2.3] |
| 第一个零件放对 | 6.7% | 7.3% | 9.5% | +0.6 [+0.3, +0.8] | +2.3 [+1.7, +2.9] |
| 零件和颜色对，不管位置 | 18.5% | 19.6% | 21.8% | +1.1 [+0.7, +1.5] | +2.2 [+1.6, +2.8] |
| 参考答案 `M` 的 loss（每 token） | 0.395 | 0.397 | 0.270 | +0.002 [0.000, +0.005] | −0.127 [−0.141, −0.114] |
| `M` 之后结束符的 loss | 4.60 | 1.49 | 1.42 | −3.11 [−3.72, −2.58] | −0.07 [−0.11, −0.03] |

对照组比冻结模型好一点点（整块正确 +0.3 个百分点），增强组比对照组的提升是它的 3 倍。

按 `M` 的大小看整块正确的比例（冻结 / 对照 / 增强）：1 件 7.1% / 8.0% / 12.1%；2–4 件 5.7% / 6.1% / 6.6%；
5–10 件 0.3% / 0.3% / 0.5%；11 件以上都是 0。`M` 越大越难整块写对，增强的提升在 1 件时最明显；
"第一个零件放对"相对对照组在每个大小上都提升约 2 到 4 个百分点。完整的分组表在集群的 `runs/nzd-supertry/eval_v2/report.md`。

### 原有能力有没有受损

在整条序列上的 loss（每 token），val 的 150 个模型：

| 序列 | 冻结 | 对照 | 增强 |
|---|---:|---:|---:|
| 官方自带的序列 | 0.281 | 0.279 | 0.281 |
| 我们的深度优先序列 | 0.286 | 0.277 | 0.280 |
| 公开采样器的原始顺序（训练时都没见过） | 0.702 | 0.707 | 0.437 |
| 官方自带序列的结束符 | 0.80 | 1.00 | 1.66 |

- **主体没有受损。** 三个模型在官方序列上的 loss 相同。
- **增强组学到的不只是"`M` 排最后"。** 公开采样器的原始顺序两组训练时都没见过，增强组在它上面的 loss 从 0.70 降到 0.44，
  对照组不变。说明它学到的是更一般的"可以接在不在路径上的零件"。
- **结束位置变差了。** 两组都学会了我们序列的结尾（结束符的 loss 从 4.6 降到 1.4–1.5），
  代价是在官方序列上预测结尾变差，增强组更明显（0.80 → 1.66）。原因是我们的序列结尾和官方的不一样，见第 2 步的"目前的限制"。

### 怎么理解"仍有 62% 接在当前路径上"

这不完全是模型没学会。训练序列里不标记 `M` 从哪开始，而序列里其他所有位置都是深度优先的接法，
只有 `M` 开始的那一步会跳。测试时模型同样看不出"`G \ M` 已经写完、现在该写 `M` 了"，
所以它在前缀末尾继续按深度优先往下写，是合理的猜测。

要进一步提高，需要让模型知道该补全了，例如在 `M` 之前加一个标记，或者用文字描述说明完整模型是什么。
这超出了"纯数据增强、不标记 `M`"的设定，是否要做需要另行决定。

## 测试集

`make_test.py` 把 val 的掩码序列从 `M` 开始的地方切成两段：

- **前缀**：`G \ M` 的全部零件，按深度优先顺序。这是给模型的输入。
- **答案**：`M` 的 2k 行。这是参考答案，不给模型看。

val 的序列池用第 3 步的 `build_data.py --split val` 生成（468 个模型，3,225 对）。从中挑测试条目的规则：

| 规则 | 值 | 原因 |
|---|---|---|
| `M` 最多 20 个零件 | `--max-k 20` | 更大的 `M` 几乎不可能整块写对，采样又很慢 |
| 每个模型最多 3 条 | `--per-model 3` | 不让大模型占掉大部分测试 |
| 排除与训练模型内容相同的 val 模型 | 26 个 | 数据集里有少量模型同时出现在 val 和 sft；零件和颜色完全相同的视为同一个 |

得到 **1,208 条，来自 442 个模型**。`M` 的大小平均 5.5 件、中位 4 件；66% 的条目有跳接（`M` 的接入点不在当前路径上）。
三个模型用同一个测试文件。

val 的模型没有参与我们的训练，官方 PT 训练时也没见过。

## 怎么测

`eval_completion.py` 对每个模型、每条测试做两件事。

**1. 采样补全。** 把前缀喂给模型，采样 8 次，每次恰好写 `|M|` 个零件（写满 2k 行后强制结束）。
采样设置与官方 `generate.py` 相同：温度 1.0，top-k 20，top-p 0.95。三个模型用同样的随机种子。

每个补全和 `M` 比较，比较与书写顺序无关：把生成的零件和 `M` 的零件一对一匹配，零件、颜色、位置姿态都相同才算放对
（对称零件转 90 度算同一个位置）。打分函数是 `brickicl/eval/match.py`，和之前的探针相同。

| 指标 | 含义 |
|---|---|
| 完全正确 | 生成的恰好是 `M`，每个零件都放对 |
| 零件放对的比例 | `M` 的零件中被放对的比例 |
| 第一个零件放对 | 生成的第一个零件是 `M` 中某个零件的正确放置 |
| 零件和颜色对，不管位置 | 只看用了什么零件 |
| 第一个零件接在参考接入点上 | 生成的第一条连接指向的零件，和参考答案相同 |
| 第一个零件接在当前路径上 | 生成的第一条连接指向前缀的最后一个零件或它的祖先，即深度优先顺序下唯一会出现的接法 |
| 能解析 | 补全是合法的序列文本 |

最后两个"接在哪"的指标是诊断用的：`M` 有时可以通过另一个零件接上去，所以"不在参考接入点"不一定错，
对错以"第一个零件放对"为准。

**2. 参考答案的 loss。** 不采样，直接算模型给参考答案 `M` 的每 token loss，以及 `M` 写完后结束符的 loss。

`report.py` 把三个模型的结果按条目配对，给出各自的平均值和两两之差。置信区间用 bootstrap，按模型整体重采样
（同一个模型的几条测试一起进出），重复 2000 次。除了全部条目，还按有无跳接、`M` 的大小分组。

## 另外两项检查

`run_eval.sh` 最后用第 4 步的 `check_order_loss.py` 对三个模型各跑两次：

- `orders val`：在官方自带的 val 序列上的 loss。检查后训练有没有损害模型在原本训练顺序上的能力。
- `pool`：在 val 序列池的整条序列上的 loss，两种顺序都算。

## 用哪个 checkpoint

每组用自己开发集 loss 最低的 checkpoint（`summary.json` 里的 `best_step`）。
两组的开发集分别是各自顺序的 `sft_dev_v2`，挑选过程没有用到 val。

## 运行

在集群的仓库根目录。三个模型的补全评测加两项检查，一条命令：

```bash
source brickicl/env.sh
nohup bash nzd-supertry/step5_eval/run_eval.sh > logs/nzd-supertry.eval_v2.log 2>&1 < /dev/null &
```

输出在 `runs/nzd-supertry/eval_v2/`：

| 文件 | 内容 |
|---|---|
| `test.jsonl` | 测试集：每行一个前缀和它的参考答案 |
| `frozen.jsonl`、`plain.jsonl`、`masked.jsonl` | 每个模型在每条测试上的全部采样文本和打分 |
| `report.md` | 对比表 |
| `orders.*.txt`、`pool.*.txt` | 另外两项检查的输出 |

单独跑一个模型、或只重新出表：

```bash
python nzd-supertry/step5_eval/eval_completion.py --name masked --data runs/nzd-supertry/eval_v2/test.jsonl \
    --lora kulits/BrickNet-0.6B-PT --lora runs/nzd-supertry/train_v2/masked/checkpoint-2000 \
    --out runs/nzd-supertry/eval_v2/masked.jsonl
python nzd-supertry/step5_eval/report.py runs/nzd-supertry/eval_v2/{frozen,plain,masked}.jsonl
```

测试集和结果文件含有受限数据集的内容，放在 `runs/` 下，不入库。

## 这个测试没有覆盖的

- **告诉了模型 `M` 有几个零件。** 采样时写满 `|M|` 个零件就停。模型自己是否知道该在哪里停，只有"结束符的 loss"这一个间接指标。
- **只测了 20 件以内的 `M`。**
- **只有一种采样设置**（温度 1.0），每条 8 个样本。
- **前缀是我们的采样器写的深度优先顺序。** 用官方自带的 val 序列做前缀的情况没有测。
- **只有 0.6B，每组只训了一次**（一个随机种子）。两组之间的差别有多少来自训练的随机性，目前无法估计。
