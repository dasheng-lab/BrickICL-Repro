# 第 3 步：生成训练数据

> 状态：完成（2026-11-10）。`v2` 的训练集和开发集已在集群 `brickICL-lmz` 上生成，通过核对，
> 并用冻结的官方模型确认了顺序在训练分布内。
>
> `v1` 是同一天早些时候用旧算法生成的，顺序不在官方训练分布内，**不要用于训练**，记录在本文末尾。

## 生成了什么

数据来自 sft 划分的模型，只用连接图，不用文字描述。两个数据池在 `~/brickICL/runs/nzd-supertry/` 下：

| 数据池 | 模型数 | 序列对数 | 用途 |
|---|---:|---:|---|
| `sft_train_v2/` | 9,999 | 70,722 | 训练 |
| `sft_dev_v2/` | 300 | 2,133 | 训练时挑 checkpoint，不动 val |

两个池的模型互不重叠，都不含 val 的模型。每个池里有三个文件：

| 文件 | 内容 |
|---|---|
| `plain.jsonl` | 搭建树的深度优先顺序，即官方训练数据的顺序（对照组） |
| `masked.jsonl` | 同一棵树，把 `M` 这一段挪到最后（增强组）；第 i 行与 `plain.jsonl` 的第 i 行配对 |
| `stats.json` | 参数、用到的模型编号、跳过和丢弃的原因、`M` 的大小、接入距离 |

每行的 `source`、`round`、`nodes`、`path` 字段与官方 `paths_*.jsonl` 一致，官方 `scripts/train.py pt --paths` 可以直接读。
另有这些字段：

| 字段 | 在哪组 | 含义 |
|---|---|---|
| `order` | 两组 | 序列里每个位置对应原模型的哪个零件 |
| `k` | 两组 | `M` 的零件数 |
| `block_start` | 普通 | `M` 这一段在普通序列里从第几个零件开始 |
| `M`、`n_prefix` | 掩码 | `M` 的零件；前 `n_prefix` 个零件是 `G \ M`，评测时用它把序列切成前缀和答案 |
| `jump` | 掩码 | `M` 的接入点是否不在当前路径上，见[算法说明](../step2_sampler/README.md#两种掩码序列) |
| `lag` | 两组 | `M` 的第一个零件往回数多少件到它的父零件 |

## 数据的样子

| | 训练集 | 开发集 |
|---|---:|---:|
| 每个模型的对数（平均 / 中位 / 最大） | 7.1 / 5 / 25 | 7.1 / 5 / 25 |
| 每条序列的零件数（平均 / 中位） | 47.4 / 45 | 47.1 / 41 |
| `M` 的零件数（平均 / 中位 / p90 / 最大） | 10.3 / 7 / 24 / 50 | 10.2 / 7 / 24 / 49 |
| `M` 占序列的比例（平均） | 22% | 22% |
| 掩码序列里有跳接的比例 | 76.4% | 76.8% |
| 接入距离，掩码顺序（平均 / 中位） | 23.5 / 19 | 23.1 / 18 |
| 接入距离，普通顺序（平均 / 中位） | 6.0 / 1 | 6.1 / 1 |

普通顺序下 `M` 的第一个零件多半紧接在它的父零件后面（中位数 1）；挪到最后以后要往回数 19 个零件。

**token 数**（Qwen3 分词器）：

| | 掩码 | 普通 |
|---|---:|---:|
| 训练集总量 | 77,596,086 | 77,594,518 |
| 每条平均 / 中位 / p90 / 最大 | 1097 / 1051 / 2013 / 2758 | 1097 / 1051 / 2013 / 2750 |
| 超过 6400 的序列 | 0 | 0 |

两组的 token 总量相差 0.002%。

## 冻结的官方模型怎么看这些数据

BrickNet-0.6B-PT 不做任何训练，在开发集前 600 对上的 loss（每 token，`step4_train/check_order_loss.py pool`）：

| 序列 | 条数 | 整条序列 | 只算 `M` 这一段 |
|---|---:|---:|---:|
| 普通（深度优先） | 600 | 0.250 | 0.222 |
| 掩码，全部 | 600 | 0.264 | 0.256 |
| 掩码，有跳接的 | 461 | 0.261 | 0.262 |
| 上一行对应的普通序列 | 461 | 0.244 | 0.214 |
| 掩码，无跳接的 | 139 | 0.279 | 0.225 |

- **普通组在训练分布内。** 0.250，和官方自带序列的 0.27 相当（旧版 `v1` 是 0.74）。
- **掩码组只在 `M` 上变难。** 有跳接时，`M` 这一段从 0.214 升到 0.262；无跳接时基本不变（0.225）。
  这正是设计想要的：两组的差别集中在"`M` 接回哪里"。
- 这也是训练的起点：后训练之后，掩码组在 `M` 上的 loss 应当明显下降，而对照组不应当。

## 采样过程中丢弃了什么

训练集的 10,000 个模型里：

| 情况 | 数量 | 说明 |
|---|---:|---|
| 抽不出新的 `M` 或掩码文本重复 | 798 对 | 多为小模型，可选的子树很快用完 |
| 树是一条链，没有可挪的子树 | 8 对 | |
| 普通文本重复 | 1 对 | |
| 文本与另一个模型的完全相同 | 4 对 | 数据集里有少量内容相同的模型 |
| 因碰撞丢弃 | 0 | 两组与官方游走是同一棵树，几何不变 |

有 1 个模型一对也没有产出，所以训练集实际来自 9,999 个模型。

## 核对

`verify_data.py` 的检查全部通过：

- 两组行数相同；每条掩码序列确实是对应的普通序列把 `M` 这一段挪到最后；
- 每组内没有重复的文本；
- 训练集和开发集没有共用的模型；
- 每个池随机抽 2000 对解析回去：零件数一致，普通序列是严格的深度优先，掩码序列只在 `M` 开始处最多偏离一次，且与 `jump` 字段一致；
- 没有超过 6400 个 token 的序列。

## 可复现性

- **同一台机器上完全可复现。** `v1` 时用 32 个进程和 8 个进程各生成一次，文件逐字相同；`v2` 的随机数用法相同。
- **不同机器之间不保证相同。** 同样的命令在 Mac 上和集群上给出的文件不一样。碰撞检测是浮点计算，
  两种 CPU 上极少数边界情况的结果不同，会改变游走。所以数据要在训练的那台机器上生成。

集群上当前文件的 SHA-256 前 16 位：

| 文件 | 校验 |
|---|---|
| `sft_train_v2/masked.jsonl` | `d3fb39bec11e9a46` |
| `sft_train_v2/plain.jsonl` | `93f687e3f8d604fb` |
| `sft_dev_v2/masked.jsonl` | `8e77709048bfe474` |
| `sft_dev_v2/plain.jsonl` | `ecc5d65b1a27381f` |

## 命令

在集群的仓库根目录运行。训练集约 1.5 分钟，开发集几秒。

```bash
source brickicl/env.sh
B="python nzd-supertry/step3_data/build_data.py --split sft --seed 0 --workers 32"
$B --models 10000 --offset 0     --out runs/nzd-supertry/sft_train_v2
$B --models 300   --offset 10000 --out runs/nzd-supertry/sft_dev_v2
python nzd-supertry/step3_data/verify_data.py runs/nzd-supertry/sft_train_v2 runs/nzd-supertry/sft_dev_v2
python nzd-supertry/step4_train/check_order_loss.py pool runs/nzd-supertry/sft_dev_v2   # 需要 GPU
```

- `--models N --offset K`：可用模型先按 `--seed` 固定打乱一次，再取第 K 到第 K+N 个。不同的区间给出互不重叠的模型集合。
- 采样参数（`--parts-per-M`、`--max-M`、`--max-frac` 等）见[第 2 步的说明](../step2_sampler/README.md#参数)，这里都用默认值。
- 默认跳过少于 6 件、超过 100 件、多连通分量、颜色无法写出的模型。sft 的 67,185 个模型里有 60,970 个可用。

输出源自受限数据集，放在 `runs/` 下，不入库。

## 旧数据 `v1`（不要用于训练）

`sft_train_v1/`（71,385 对）和 `sft_dev_v1/`（2,149 对）仍在集群上。它们由旧算法生成：两组都按公开采样器的访问顺序写，
`M` 取自另一棵随机生成树。冻结的官方模型在它们上面的 loss 是 0.74（普通）和 0.69（掩码），远高于官方自带序列的 0.27，
说明这个顺序不在训练分布内。保留只是为了对照，确认不需要后可以删除（约 470 MB）。
