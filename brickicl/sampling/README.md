# 掩码采样器设计："先 G \ M，后 M"

> 状态：核心采样器、挖掉一份副本的试点、长腿测试已实现并在 GPU 上跑通（见第 9 节）；其余部分仍是设计。
> 对应项目路线图的 **第 1 步**。

已知一个乐高模型的连接图 `G`，以及要挖空的零件集合 `M`。采样器生成一条**合法的** BrickNet 搭建序列（path text），
其中 `G \ M` 的所有零件排在前面，`M` 的零件排在最后。前半段作为上下文交给模型，模型自回归地写出后半段，
再与真实的 `M` 对比。在此基础上，通过控制"上下文里有什么"（重复结构、编辑、删除），来区分模型的信息来自上下文还是权重。

## 1. 设计依据：BrickNet 的几条约定

下面的设计依赖这些约定，都已对照 `baseline/bricknet/BrickNet/src/bricknet/` 的源码确认。

| 约定 | 出处 | 对采样器的影响 |
|---|---|---|
| path text 第一行是根节点 `ID 零件名 \| 颜色`；之后每个零件是"节点行 + 边行"，边行把这个零件接到一个**更早出现**的零件上 | `tree.py` 语法 | 只要每个零件都能接到前面已经放置的零件上，任何顺序都合法 |
| 节点编号 `a, b, …, aa` 只起标注作用，父节点引用**按位置**解析 | `parse_node`：labels are decorative; identity is positional | 同一个零件出现在不同位置，编号就不同。"标签平移"会自然出现，不需要另外构造 |
| 训练数据来自 `sample_collision_free_tree`：随机根节点 + 随机 frontier walk（每步从"已放置零件伸出的所有边"里均匀抽一条），带碰撞检测，最多 100 个零件 | `graph.py` | 我们的采样沿用同样的游走方式，生成的序列就在训练分布的支撑集内 |
| 训练时每行只有一条序列加 EOS，**不会把多个模型拼成一行** | `scripts/train.py` 的 `Collator` | 冻结的 BrickNet 从没见过"示范 EOS 查询"这种多实例上下文，所以第 1 步只用单序列格式（见第 5 节） |
| 连接图里有并行边（同一对零件之间有多处连接）和环；一条序列只写出生成树上的边 | `_adjacency`、`_build_tree` | 挖空时要保证剩下的部分仍然连通；"三段论"划分需要用到环 |
| 同一条边反向遍历时，`_make_tree_edge` 会自动换算参数（yaw/slide 取反等） | `graph.py` | 换根、反转方向时，相对变换不用我们自己重算 |
| `_build_tree(graph, order, parent_of)` 会按访问顺序重新编号，并生成每条树边 | `graph.py` | 采样器只需要给出访问顺序和每个零件的父边，编号重建和变换都交给它 |

## 2. 数据现状（val 集，512 个模型）

| 统计量 | 数值 | 含义 |
|---|---|---|
| 连通分量 | 全部为 1 个 | 不需要处理多分量 |
| 零件数 p10 / 中位数 / p90 / 最大 | 6 / 18 / 57 / 100 | 都在 BrickNet 的 100 件上限以内 |
| 每对相连零件之间的连接数（中位数） | 1.46 | 并行边很常见；"换一条边"必须换成**不同的零件对**才算真正的新信息 |
| 有环的模型（简单图） | 324 个（另有 188 个是树） | "三段论"划分只能在有环的模型上做 |
| 删掉单个零件后剩余部分仍连通 | 中位数 59% 的零件满足 | 很多零件是"关节点"，删掉会断开 |
| 随机连通的 M，删掉后剩余仍连通的比例 | \|M\|=1：0.61，2：0.41，4：0.18，8：0.10 | 不能靠"随机挖、不合法就重来"，必须**按构造保证合法**（见 4.1） |
| 含 ≥2 份不重叠的相同双零件结构（零件、颜色、连接参数都相同） | 270 个模型 | "上下文证据"实验的主要数据来源 |
| 含 ≥2 份不重叠的相同三零件链 | 202 个模型 | 可以做更大的 M |

（统计用的是临时脚本，以后实现 `motifs.py` 时要用正式代码复核。）

## 3. 核心算法：带屏蔽集的 frontier walk

**输入**
- `G`：一个模型的连接图（`bricknet.load_graphs` 得到的 `Graph`，只取一个连通分量）。
- `M`：要挖空的零件集合（图节点编号）。
- `seed`：随机种子。
- 可选约束：根节点；指定某些零件必须用哪条父边；某个子结构的内部访问顺序（第 6 节的泛化划分会用到）。

**前置条件**（不满足时直接拒绝，不会生成坏数据）
1. `M` 非空，`M` ⊂ V，且 `V \ M` 至少有 2 个零件。
2. `G[V \ M]` 连通，这样前缀才是一条完整的游走。
3. 完整模型在 v0.1.1 下无碰撞。val 中有 508/512 个满足。因为所有零件都是真实位置，顺序不会带来新的碰撞。

**步骤**
1. **选根**：在 `V \ M` 里均匀随机选一个根，也可以由约束指定。
2. **阶段一（前缀）**：从根开始做 BrickNet 式的 frontier walk，但边界上**屏蔽所有指向 `M` 的边**。
   每步从边界里均匀抽一条边 `(父, 子)`，记下 `parent_of[子] = (父, 边编号, 方向)`，并把子零件伸出的新边加入边界。
   由于 `G[V \ M]` 连通，这个阶段一定会把 `V \ M` 放完。
3. **阶段二（目标）**：解除屏蔽。边界里现在只剩指向 `M` 的边，继续同样的随机游走，直到 `M` 全部放完。
   因为 `G` 连通，`M` 一定能全部接上。
4. **组装**：用 `_build_tree(G, order, parent_of)` 生成 `Tree`，再用 `serialize_tree` 得到 path text。
   - 前 `|V\M|` 个零件对应的 `1 + 2(|V\M|-1)` 行是**前缀**（以 `\n` 结尾）。
   - 剩下的 `2|M|` 行是**参考答案**。

**性质**
- 每条输出都是合法的 BrickNet 游走。"`M` 恰好最后才被访问"只是 BrickNet 原采样器里一个概率较低的结果，所以输出仍在训练分布的支撑集内。
- 前缀恰好是 `G \ M` 的一条游走。父节点编号和相对变换都由 `_build_tree` 重建，不需要手工修补引用。
- 给定 `seed`，结果完全确定，可以复现。
- 阶段二的顺序不唯一，参考答案只是其中一种。**评测必须与顺序无关**（见第 7 节）。

## 4. 如何选择 M

### 4.1 随机连通子装配（第 1 步默认）

1. 对 `G` 做一次随机 DFS，得到生成树 `T`。
2. 在 `T` 里找出所有大小恰好为 `k` 的**完整子树**，从中均匀抽一个作为 `M`。
3. 拿掉 `T` 的一棵完整子树后，剩下的部分在 `T` 中仍然连通，所以在 `G` 中也连通。`M` 本身也连通。两者都按构造成立，不需要重试。
4. 如果这棵 `T` 里没有大小为 `k` 的子树，就换一个种子重新生成 `T`，最多重试若干次。

`k` 初步取 {1, 2, 4, 8}，同一组实验固定 `k`，以控制生成长度（docx 的要求）。

### 4.2 重复结构的一个副本（上下文证据）

1. 找出 `G` 里两份以上**不重叠且同构**的子结构 `S₁, …, S_c`：零件、颜色、内部连接的接口和角度都相同。例如马的四条腿、车的四个轮子。
2. 选一份作为目标副本 `S*`，令 `M` ⊆ `S*`。`M` 可以是整份副本，也可以是它的末端一部分。其他副本留在前缀里，作为上下文证据。
3. 检测方法：先用带标签的 WL 哈希找候选，再用带标签的子图同构（VF2）确认。参与比较的标签是零件、颜色，以及边的族、接口编号、yaw、flip。
   - 左右镜像件（零件编号不同）先**不算**副本。

### 4.3 对照：唯一结构

`M` 取自没有同构副本的子结构。这时上下文里没有可以抄的证据，用来测模型只靠先验能做到什么程度。

## 5. 上下文格式与条件

**格式 A：单序列（第 1 步，冻结的 BrickNet）**
- 上下文就是同一个模型的前缀。"示范"是同一模型里的其他副本，和 docx 里"上下文信息仅有待补全乐高实例"一致。

**格式 B：多实例（诊断测试与后训练）**
- 形式为"示范序列 + 分隔符 + 查询前缀"。已用冻结的 BrickNet-PT 做 `G → G/M` 诊断测试：完整示范与第二个查询的已知路径严格一致，见 [评测与结果](../eval/results/matched_r4_p1.md)。
- 冻结的 BrickNet 未接受过这种带内部 EOS 的训练格式，因此该测试同时包含提示格式迁移；后训练阶段仍需让训练和测试使用相同格式。

**格式 A 下的条件**（都针对 4.2 的样本，同一个 `M` 成对比较）

| 条件 | 怎么构造 | 期望答案 |
|---|---|---|
| 有证据 | 其他副本都在前缀里 | 原始的 `M` |
| 无证据 | 从 `G` 里删掉其他副本（删完必须仍连通，否则舍弃这个样本），`M` 和它的接入点不变 | 原始的 `M` |
| 一致编辑 | 其他副本和 `M` 一起做同样的编辑（换色、换件、延长） | 编辑后的 `M` |
| 冲突编辑 | 只编辑其他副本。目标副本中已经给出的部分 `R = S* \ M` 保持原样，由它指定目标设计 | 原始的 `M`，同时统计"跟随错误示范"的比例 |
| 等长无关历史 | 格式 A 里很难做到长度严格相等，先按前缀长度分层近似；严格版本放到格式 B | 原始的 `M` |

**图编辑操作**（`edits.py`，编辑后都要重新做碰撞检测）
- **换色**：只改颜色，几何不变，总是合法。
- **换件**：只在"接口布局完全相同"的零件之间替换，需要先从 `labels.json.xz` 建一张兼容表。
- **延长**：在链条末端沿同一接口方向接上末端零件的拷贝。马腿实验用的就是这个操作：其余三条腿延长，挖掉第四条，看模型生成长腿还是短腿；对照组的腿不做修改。

## 6. 四种泛化划分（作为采样约束）

设 `A`、`B` 是同一模型里的两份副本，`φ: A → B` 是它们之间的同构映射。`A` 完整地出现在前缀里；`B` 的一部分 `R` 在前缀里，其余部分 `M` 放在最后。
四种划分只改变 `B` 的序列化方式，零件集合和真实几何不变，所以性能差异只能来自推理类型，而不是数据难度。

| 划分 | 对 `B` 的约束 | 实现方式 |
|---|---|---|
| Rephrasing（改写） | `B` 的内部树边、内部访问顺序和根的对应关系都和 `A` 相同（经 `φ` 映射）；边行逐字相同，只有编号因位置不同而平移 | 游走进入 `B` 后按 `φ(A 的内部顺序)` 走（模板约束） |
| Reversal（反转） | `B` 用的是 `φ(A 的内部树边)`，但从另一端开始：根取 `φ(A 最后放的零件)`，所以每条边都反向书写 | 指定 `B` 的入口零件和父边；参数反向由 `_make_tree_edge` 自动处理 |
| Syllogism（三段论） | `B` 里至少有一个 `M` 零件，经由一条边接入，这条边在 `A` 中的对应边**没有写在 A 的序列里**（是 A 的非树边），而且连接的是**另一对零件** | 指定这个零件的父边；只适用于副本内部或副本与主体之间有环的情况 |
| Category holdout（类别留出） | `B` 中 `R` 里的一个零件被换掉（先换色，以后再换件），`M` 里接在它上面的零件需要继承原来的连接 | 先对 `B` 做图编辑，再按普通约束采样 |

三种约束合起来就是"受约束的 frontier walk"：每一步只从满足约束的边里抽。

- **约束类型**：指定根；指定部分零件的父边（白名单）；指定某个子结构的内部访问顺序。
- **失败处理**：如果约束导致边界为空，就拒绝这个样本，并记录原因。
- **样本筛选**：每种划分实际能用的样本数，要等 `motifs.py` 实现后再统计，比如三段论需要副本内部有环。

## 7. 配套的评测接口

**生成**
- 提示词就是前缀文本，以 `\n` 结尾。下一个 token 应当是新零件的编号 `i2id(|V\M|)`（编号从 0 开始）。
- 沿用 `generate.py` 的 `StopAfterNewlines`：生成满 `2|M|` 行之前屏蔽 EOS，满了就停。
- 采样方式取 NS（top-k 20, top-p 0.95）和贪心两种。

**与顺序无关的匹配**
1. 把"前缀 + 生成结果"解析成 `Tree`，用 `decode_graph(tree_to_graph(...))` 算出每个零件的绝对位姿。参考答案按同样方法计算。两者的前缀相同，所以在同一个坐标系里。
2. 逐个比较生成零件和 `M` 中的零件：零件和颜色要相同，位姿要等价。
   - 位姿用"所有接口点的世界坐标集合"比较，这样对称零件转 180° 等情况会自动算作同一位姿。容差暂定 1 LDU。
3. 用匈牙利算法做一一匹配。

**指标**（与 proposal 对应）
- 零件准确率：零件 + 颜色，不看位置。
- 放置准确率：零件 + 位姿，相当于 proposal 里的连接准确率。
- 完全补全率：`M` 全部放对。
- 下一步准确率：第一个生成的零件，是否等于 `M` 中某个当时可以接上的零件，且位置正确。
- 诊断项：解析失败率、与前缀碰撞的比例。这一项不计入主指标，因为碰撞不在项目范围内。

**打分式评测**（方差更小，适合测 ICL 增益）
- 对真实后缀做 teacher forcing，计算 log-likelihood。为消除顺序的影响，对 R 种后缀顺序取平均。
- ICL 增益 = 同一个样本在"有证据"和"无证据"两种条件下的似然差。
- 统计上用按源模型分组的配对 bootstrap。

## 8. 输出格式（jsonl，每行一个样本）

| 字段 | 内容 |
|---|---|
| `source` | 模型 id（`val.npz` 的行号，与 `captions_val` 的 id 对应） |
| `split` / `strategy` / `condition` | 数据划分；挖空策略（`subtree-k` / `motif` / `unique`）；上下文条件 |
| `M` | 挖空零件的图节点编号 |
| `order` | 完整访问顺序（图节点编号），前 `n_prefix` 个是前缀 |
| `n_prefix`, `k` | 前缀零件数，`k = |M|` |
| `prefix` / `target` | 前缀文本 / 参考答案文本 |
| `edits` | 做过的图编辑（换色、换件、延长）及其参数 |

## 9. 代码结构

已实现（标 * 的是试点版本，与上面的设计有出入，见各文件开头的说明）：

```
brickicl/sampling/
├── README.md         本文件
├── masked_walk.py    核心：带屏蔽集的 frontier walk；可选 blocks，让指定副本在前缀里连续写出（第 3 节）
├── missing.py *      重复的"悬挂"子装配（腿、轮子……）：桥边 + WL 哈希，暂无 VF2（4.2）

├── build.py          命令行：val → 挖掉一份副本的有证据 / 无证据样本 jsonl
└── build_stretch.py  命令行：长腿测试，原样 / 加长 / 删除三种上下文 × 短 / 长两个答案

brickicl/eval/
├── match.py          与顺序无关的匹配：接口点世界坐标集合 + 匈牙利匹配，容差 3 LDU（第 7 节）

├── length_probe.py   长腿测试：log p(长) − log p(短)、自由采样、给开头采样（--prime）

```

尚未实现：`motifs.py`（VF2 确认、非悬挂的重复结构）、`splits.py`（四种泛化划分）、

## 11. 待讨论

- `k` 的取值，以及前缀最短长度（例如至少 4 个零件）。
- 前缀的游走方式：完全模仿训练分布（随机根、frontier walk），还是固定根或改用 BFS，以减小方差。
- 格式 B 的分隔符设计，以及要不要也在冻结的 BrickNet 上测一下（作为分布外参考）。
- 格式 A 下"等长无关历史"的严格做法。
- 判定重复结构时，yaw 的容差和镜像件怎么处理。
- 换件兼容表的定义。
- 位姿匹配的容差。
- val 与训练集之间是否有近似重复的模型（BrickNet 的划分是按模型做的，但可能有改色、改件得到的近亲），需要先查重。
