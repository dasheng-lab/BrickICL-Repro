# GRPO v2.1：实现与评测

v2.1 是 GRPO 消融的第一组：在 r1 上只改奖励（F1 → F2），并且训练、开发集、加长参照开发集**都给 M 的第一个零件**
（sunshq 的 p1）。训练 2026-11-21 22:52 → 2026-11-22 09:24 UTC（400 步，约 10.5 小时，单卡 H20）。
输出在服务器 `~/RL/runs/v2.1/`。公开代码、论文结果与复现入口见[仓库说明](../../../README.md)。

## 1. 为什么做 v2.1

r1（第 401 步停，选第 300 步）有三个问题：

1. 越训越早停：开发集空补全第 300 步后从 0.18 升到 0.27；
2. 给第一个零件、参照加长时，46% 的样本停在目标之前，sunshq 口径的 val Δlog-odds 从起点的 +2.71 降到 +1.84；
3. 训练里没有东西奖励"照着参照写"。

v2 方案一次改四处（F2 奖励、失败 −0.1、固定损失分母、25% 加长参照题）。为了说清每一处的作用，改成一次只改一处。
先做 F2，理由：

- 早停是 r1 变差的主要原因，F2 让"少写"比"多写"代价大，作用在每一道题上；
- F2 与 F1 在同样的情况下为 0（没有放对的零件或解析失败），所以保留哪些组、训练题顺序、采样种子都和 r1 一样；
- 每步用时与 r1 相同（−0.1 会让保留的组翻倍）。

## 2. 实现

### 2.1 与 r1 的差别

| 项 | r1 | v2.1 |
|---|---|---|
| 奖励 | Pose F1 = 2m / (n_p + n_t) | **F2** = 5m / (4·n_t + n_p)（`--beta 2`） |
| 解析失败 / 空补全 | 0 | 0（不变） |
| 损失归一化 | ÷ 本批 token 数 | 不变 |
| 训练题 | 普通补全题，`|M| ≤ 10` | 同一池，**给 M 的第一个零件**（`--first-part`） |
| 步数 | 500（第 401 步停） | 400 |
| 开发集 | 600 题 × 4 | 给第一个零件后 477 题 × 4；另加加长参照开发集 187 对 × 4（只测，不训练） |

其余与 r1 完全相同：起点 `runs/start_merged/masked`（官方 PT + nzd 第一轮 masked checkpoint-2000 合并），
Dr. GRPO（优势 = 奖励 − 组均值，不除标准差），逐 token 损失，k3 KL 系数 0.01，LoRA r32 / α32，学习率 2e-5（预热 10 步），
梯度裁剪 1.0，每轮抽 64 题、每题 16 个样本、至少保留 16 个组内有差异的组（最多抽 3 轮），vLLM 采样，
每 50 步存档并测开发集（每题 4 个样本），种子 0。

### 2.2 F2 奖励

F-beta = (1 + β²)·m / (β²·n_t + n_p)，β = 2 时漏写一件的代价约是多写一件的 4 倍。最优仍是正好写完 M
（全对时多写 4 件，k = 3 得 0.79），不会无限写长；撞到 token 上限的样本通常停在半行、解析失败，得 0。
实现在 `common/rewards.py`：`f_beta()`，`completion(..., beta, fail)` 同时返回 `reward_f1`（r1 的奖励）和 `reward`（F-beta）。
CPU 核对（`check_v2.py`）：β = 1、失败 0 时与 r1 存下的奖励完全相同（800 个样本，最大差 0）。

### 2.3 给第一个零件（`--first-part`）

与 sunshq 的 p1 相同：M 的第一件（两行）从目标移到前缀末尾，n_prefix + 1，模型写其余 k − 1 件；`|M| = 1` 的题去掉。
`grpo.py` 的 `give_first_part()` / `first_part_all()` / `give_first_part_pairs()`：

- 训练题 44,049 → 36,813 道，开发集 600 → 477 题；
- 加长参照开发集 187 对全部保留；"多出来那种零件"的个数在变短的目标上重数（命中阈值 = 加长那一行变换后的个数，同 sunshq 的 p1），
  平均 5.63 → 4.75。

核对：对 sunshq 的 36 个来源 × 两种目标，由 p0 变换得到的前缀、目标、n_prefix 与他的 p1 输入 72 / 72 完全相同。

### 2.4 加长参照开发集（`--stretch-dev`）

`build_stretch_prompts.py` 从训练池以外的 4,000 个 sft 模型里找有重复、可加长肢体的模型（只读调用 nzd 的
`held_out_row`、`stretch`、`stretchable_group`），留出一份作 M，另一份放在前缀最后作参照，每份写成两种条件：

- **加长**：所有副本都加长 r = 1–5 件，M = 加长后的那份；
- **原样**：模型如数据集，M = 原来那份。

共 187 对（98 个模型），与训练池、`sft_dev_v2` 无重叠，val 一个都不读。每个 checkpoint 每题采 4 个，报：

- 命中率：写出的"多出来那种零件"不少于长目标的个数（sunshq 的规则）；
- Δlog-odds = 按对平均 ln((k + .5) / (n − k + .5))，加长减原样；
- 停在目标前的比例。

### 2.5 对照：r1 给第一个零件

r1 训练时没给第一个零件。为了同口径比较，用 r1 的每个 checkpoint 在**给第一个零件**的开发集和加长参照开发集上重新采样
（`eval_stretch_dev.py --first-part --dev-test`，同一个 Sampler、种子 + 7，写 `runs/r1/train/grpo/dev_p1/`、`dev_stretch_p1/`）。
v2.1 第 0 步与 r1 checkpoint-0 完全相同（开发集 F1 0.2093，加长参照 F1 0.4783），对照成立。

**局限**：v2.1 与 r1 的差同时包含"F2"和"训练时给第一个零件"两处，不能完全归到 F2；要分开需要再跑"r1 + 给第一个零件、F1 奖励"。

### 2.6 运行

## 6. 结论

（开发集部分；val 跑完后补全）

1. **v2.1 在开发集上全面好于 r1**，且差距越训越大：第 400 步 F1 奖励 +0.077 [+0.061, +0.094]，
   Δlog-odds +1.48 [+1.24, +1.71]，空补全 0.031（r1 0.169），参照原样时写出长特征 0.041（r1 0.049，更少"无端写长"）。
2. **没有 r1 的后期漂移**：r1 第 100 步后 F1 不再涨、Δlog-odds 一路降、第 400 步空补全升到 0.17；
   v2.1 的 F1 一直涨到第 400 步，Δlog-odds 在第 150–200 步短暂下降后回升，第 400 步与第 100 步峰值差不显著。
3. **F2 想解决的"停短"没有变好**：普通开发集 0.385（r1 0.336）；加长参照时第 350 步后才低于 r1（0.239 vs 0.349）。
   所以提升多半来自"训练时给第一个零件"，F2 本身的作用说不清（缺"F1 + 给第一个零件"对照）。
4. 下一组 **v2.2 = v2.1 + 25% 加长参照训练题**（同样给第一个零件，`PRESET=v2.2`），直接奖励"照着加长的参照写满长腿"，
   val 不比 r1 差就启动。
